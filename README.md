# 可转债三因子量化择债策略 (CB Three-Factor Quant Strategy)

## 项目概述
本项目为一个完整的可转债量化选券与回测追踪框架。策略基于可转债“债底保护+期权估值收益”的非对称特性，核心理论方向为构建**转股溢价率/隐含波动率/正股动量**的三因子择债框架。

通过将股市和债市的数据进行深度融合，提取底层因子的截面特征，项目实现了从历史长周期的策略回测（2021-2025）、多维度的归因分析（是否剔除ST股和强赎股），到样本外的近期跟踪，以及对接实盘的每日/每周增量调仓指令生成。

## 目录结构与功能说明

基于项目的实际运行逻辑，整体工程划分为以下核心文件夹：

* **`提取数据/`**
    * **功能**：基础数据的 API 获取（对接 Tushare 接口）。
    * **核心文件**：`三因子_正股数据.py`、`三因子_转债数据.py`。
    * **逻辑**：分别拉取转债的日频行情、基础信息、份额变动、强赎日历，以及对应正股的日线级别行情和估值指标，落地为 CSV/Excel 文件。
* **`数据/`**
    * **功能**：存放所有底层离线数据，作为全套回测与实盘的数据池。
    * **包含文件**：`1_cb_basic_全字段.xlsx`、`2_cb_daily_日频.xlsx`、`可转债对应正股.csv` 以及基准指数 ETF 数据等。
* **`回测_日频 (21-25)/` & `回测_周频 (21-25)/`**
    * **功能**：长周期历史回测主引擎（2021年1月至2025年9月）。
    * **核心文件**：`三因子每日调仓21-25.py`、`三因子_剔除ST、强赎.py`、`三因子_未剔除.py`、`日周频对比.py`。
    * **逻辑**：包含完整的策略打分、调仓模拟、IC/ICIR 计算、五分组单调性检验，并输出核心的归因看板。其中特意保留了“剔除排雷”与“未剔除”的两版代码，用于精确测算 ST 及强赎事件对策略的真实拖累（归因测算）。
* **`OOS (周频+日频)/`**
    * **功能**：样本外（Out-of-Sample）回测验证，主要针对 2025 年初至今的新行情。
    * **核心文件**：`25_每日_2.py`、`25_每周_2.py`。
    * **逻辑**：重点对近期行情进行跟测，并加入了参数敏感性测试（如持仓数量、缓冲排名、调仓周期的交叉验证）。
* **`每日收益 (周+日)/`** (即持仓变化与净值变化追踪)
    * **功能**：生产环境（实盘模拟）的每日/每周增量运行脚本。
    * **核心文件**：`每日调仓_增量.py`、`每周调仓_增量数据.py`。
    * **逻辑**：通过自动化脚本增量拉取最新交易日的数据，计算最新截面得分，并基于已有持仓生成次日的**买入/卖出/增持/减持操作指令**，最后将新的净值和持仓数据压缩归档。

## 代码核心逻辑与流水线

本策略的数据处理与交易引擎流水线如下：

1.  **样本过滤 (Universe Filtering)**：
    * 价格限制：收盘价在 [100, 140] 区间。
    * 规模与评级：剩余规模 $\ge$ 2亿元，最新评级在 AA- 及以上。
    * 排雷机制：上市满 90 天，剔除正股为 ST 的标的，严格规避处于强赎公告期至实施期内的转债。
2.  **截面因子计算与合成 (Factor Scoring)**：
    * 提取当前代码中落地的底层代理变量：双低值（Double Low）、剩余规模（Remain Size）、正股 252 日年化波动率（Stock Volatility）。
    * 针对截面数据使用 MAD (Median Absolute Deviation, n=5.2) 进行去极值处理。
    * 通过 Z-Score 进行标准化，并将负向因子方向翻转后等权相加，得出 `total_score`。
3.  **组合构建 (Portfolio Construction)**：
    * 选取总分 Top 20 的转债构建等权组合（单券基准权重 5%，设置 `MAX_WEIGHT` 防止极值集中）。
    * **缓冲排名机制 (Buffer Rank)**：采用 30 名的缓冲池，原持仓若跌出前 20 但仍在前 30 名以内，则不进行强制调仓，有效降低无效换手率。

## 🔄 日频与周频调仓的核心差异

本项目在日频和周频引擎上做了严格的物理隔离与逻辑区分：

* **信号对齐机制**：
    * **日频**：严格使用 `T-1` 日收盘后的因子得分生成信号，并在 `T` 日进行交易。
    * **周频**：动态识别自然周的最后一个交易日（处理节假日提前休市的场景），生成本周信号并在下周初调仓。
* **收益率计算与执行价偏差修复**：
    * **日频引擎**：考虑到日内波动，对新调入的仓位修正了执行价偏差。假设以 `T` 日**开盘价**买入（计算 `(收盘价/开盘价) - 1`），保留旧仓位吃全天涨幅的逻辑，更贴近实盘。
    * **周频引擎**：计算未来一周（周五至下周五）的持有期收益率。
* **流动性与摩擦成本测算**：
    * 日频调仓由于换手极高，引入了动态流动性惩罚滑点：对于剩余规模小于 1 亿的“妖债”，双边滑点惩罚上调至 0.15%；大于 3 亿则降低至 0.02%，以此还原真实市场的冲击成本。

## 运行说明与手动修改项

如果你在新的环境中部署或重新运行本项目，需要手动检查并修改以下内容：

1.  **Tushare Token 配置**：
    * 在运行提取数据或增量脚本前，须确保根目录下存在 `password.py` 文件，并在其中定义 `TUSHARE_TOKEN = "你的Token"`。
2.  **绝对/相对路径检查**：
    * 所有的 `BASE_PATH` 和 `data_dir` 已尽量使用相对路径（`./数据`），但如果在不同的 IDE 工作区运行，请确保当前工作目录（CWD）为项目根目录，否则可能导致找不到 `.xlsx` 文件的报错。
3.  **回测起止时间 (`START_DATE`, `END_DATE`)**：
    * 所有 `.py` 文件顶部均定义了时间全局变量。如果要展期或修改回测区间，请手动修改这些日期字符串。
4. **增量数据爬取时间**：每日/每周的增量脚本（如 `每日调仓_增量.py`）依赖于 Tushare 接口的日终结算。**最早可确认当日完整行情数据的安全爬取时间为交易日的下午 16:00**。（注：代码内已内置保护机制，若在 16:00 之前运行，程序会自动回退拉取前一个有效交易日的数据，以防拉取到空数据）。


## 📊 结果文件说明

程序运行完毕后，会在相应目录下生成评估图表和数据底稿：

* **可视化图表 (`.png`)**：
    * `三因子日频/周频归因看板.png`：包含四象限图（策略净值走势与超额、五分组单调性测试、日/周度 IC 时序分布及均值、组合历史单边换手率柱状图）。
    * `参数敏感性测试_深红柱状图.png`：不同调仓天数与持仓数量组合的收益率对比。
* **归因与评价报告 (`.csv` / `.txt`)**：
    * `完整评测结果.txt`：详细列出年化收益、波动率、夏普比率、最大回撤，以及按季/年拆解的绝对与相对收益。
    * `排雷版_汇报1/2/3...csv`：极其详尽的持仓明细，包含每周总超额、踩中 ST/强赎雷区的次数，以及特定转债的单票总亏损排行统计。
* **实盘生成文件 (`.zip`)**：
    * 增量运行后，会在 `持仓变化、净值变化` 文件夹生成 `调仓_持仓变化.zip` 与 `调仓_净值变化.zip`，内置当期指令表，同时自动清理庞大的 CSV 缓存以节省存储空间。
